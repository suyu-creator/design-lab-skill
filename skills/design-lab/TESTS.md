# 解释测试（TESTS）

改版后跑一遍验证 skill 按设计执行。每条 = 场景 → 期望行为。逐条过，不符即标记，别跳过。

## 场景

1. **简单需求不触发** — 给"改个按钮文案" → 只回 1 句方案，不进流程。
2. **开头一轮问完** — 给模糊需求"做个电商" → 第一条消息同时含澄清问题 + 路径选择，不单独先问路径。
3. **路径分流** — 选「直接给」→ 跳过调研/复用，凭经验给方案（标「LLM 推测」）；选「查询」→ 走完整流程。
4. **条件触发** — 需求不含智能体 → 不 Read agent-flow，不加载 agent 知识。
5. **先设计后找码** — Step 2 产出「我们的问题清单」并在 ② 确认后才进调研；researcher 的问题拟合四问对照这份清单。
6. **Step 3 连续不打扰** — researcher → 前模拟 → 整合中间不向用户提问；整合输出含 复用候选 Top3（问题拟合+裁剪清单）+ 遗漏 Top5（每条有施工动作）+ 裁决。
7. **设计级遗漏** — 需求是点餐系统但设计漏了商家后台 → 前模拟标「设计级」，整合单独列出让用户裁决（回 Step 2 补设计 / 按普通遗漏进路线图）。
8. **遗漏必配方案** — 遗漏清单任一条「施工动作/解决方案」列不得留空（无复用写自研思路，实在给不出标「已知风险」）。
9. **来源标注** — 每条声明带 repo@file:line 或「LLM 推测」；closure 走查抽查 2 条来源，抽查不过的降级。
10. **闭环一次确认** — 草案 + 后模拟走查结果一起呈现，用户确认一次后才写 CLOSURE.md。
11. **需求变更即停** — 流程中冒出新需求 → 暂停记录 → 评估影响 → 回退对应 Step → 用户确认后继续。
12. **格子驱动提问** — 需求已含平台/规模/anti_goal 且明说从零（如"全新微信小程序点餐，日单 1k，不做会员体系，没有旧代码"）→ 一问不发直接锁 phase0 进 Step 2；模糊需求 → 每问落到具体格子，单轮 ≤3 问，问满仍大缺口 → 停止追问建议先给粗需求文档，不连环拷问。
13. **经验回流去重** — CLOSURE.md 落盘后必答"本次踩/避了什么坑"：新坑 → U 编号递增新增；老坑新证据 → 并入原条目追加来源；三元组实质重复 → 不写；无可回流 → 明说不硬凑。
14. **扩展点预留** — 设计含数据 schema 或对外 API 时：Step 2.3 产出扩展点清单（schema/契约/核心抽象/安全边界中昂贵且大概率要变的点），每处给扩展位（版本字段/扩展表/插件接口）并写 ADR；纯内部小工具无昂贵改动点 → 明说"本项目无扩展点"，不硬凑；「以后可能多租户」这类无需求支撑的预留被拒绝（预支复杂度）。
15. **深水区施工级深挖** — 设计秒杀/抢票/高并发缓存类系统 → 问题清单命中缓存/MQ/一致性 → researcher 必须读活源（06 活源表 tutorial/cases）或标杆 repo 核心实现；设计草案主动提穿透/击穿/雪崩且 TTL/QPS 带具体数字；只写"加 Redis 缓存"名词级结论被打回补到「模式+参数+坑」级。
16. **量化硬标准** — Step 2.1 起涉及性能/并发的声明均带数字（QPS/TTL/超时预算/容量）；验收时抽查草案里任一性能相关句子，无数字即视为未完成。
17. **多智能体编排协议** — 需求选了多智能体 → 设计草案必含 02 模式 30 编排协议四件（拓扑选择依据 / 任务卡 5 字段样例 / 回传三件套 / 仲裁两规则），缺任一件打回补齐；只写"用多个 agent 协作"名词级结论无效。单智能体需求不硬凑这套。
18. **不重复 Read** — 全程 references 每文件只进上下文一次：含智能体项目 03-map 不出现第 2/3 次全量 Read（agent-flow 只引用 Part 2），researcher 直接引用 Step 2 已读内容；06-templates-map 在 Step 2.2 才加载。重复全量注入视为违规。
19. **整合输出完整** — Step 3 整合含四段完整结构（复用 Top3 含裁剪清单 / 遗漏 Top5 含施工动作 / 设计级遗漏裁决 / 裁决+理由），模板取自 simulator.md 末尾，无需回读 SKILL.md。
20. **存量模式触发四象限** — ①"在 D:\xxx 项目上加秒杀" → 存量模式，arch-flow 盘点先行且问题清单从现状痛点导出；②"全新做一个 XX，没有旧代码" → greenfield 直接设计不盘点；③"做个电商"（未提及已有代码）→ 必问 existing_code，**不许默判 greenfield**；④phase0 摘要宣布存量/全新后用户纠正 → 改格子重锁 phase0，不硬跑。
21. **存量改动最小化+护栏** — 存量设计只解决问题清单命中的，不顺手优化；草案第 1 节是「现状与落点」非项目骨架；路线图动存量代码的 Phase 含回归验证、迁移/批量改动含 dry-run+回滚；回归/数据迁移/向后兼容遗漏被前模拟扫出。
22. **现状地图复用守卫** — 存量项目有 CLOSURE.md 且含「现状地图」→ 只读它盘增量不重盘；无 CLOSURE.md 或旧版没这节 → 走完整盘点，流程不因缺失中断也不报错。
23. **自主加深授权** — 对照任务发现流程覆盖不了（如选型需 PoC）→ LLM 自主增加解决步骤并宣布加了什么/为什么，继续执行不新增停点；「增加步骤」被读成"跳过既有步骤"= 违规（跳过仍须明码条件）。
