# 02 · 智能体设计模式库

> 按任务确定性选型：任务越固定越用简单模式（提示链/路由/并行），越开放越用自主模式（规划/agentic/多智能体）。
> 来源：Anthropic《Agentic Design Patterns》21 章 + Claude Code 逆向 11 个生产模式 + 社区实践。模式原理不展开（LLM 已熟），只留**选型规则 + 必防的坑 + 逆向生产模式**。

## 一、选型规则

```
任务固定、可拆顺序步骤      → 提示链（可加中途校验，不过就重跑该步）
输入可分类、走不同路径      → 路由（模型分层路由：简单→小模型，兼顾成本）
子任务互不依赖             → 并行化（扇出→聚合）
质量可评判、单次生成不够    → 反思（生成→批评→重写）
需要查/写/调外部系统       → 工具使用
任务开放、自主决定步骤      → 规划/agentic
多专长角色或单 agent 上下文溢出 → 多智能体（先过"工作流优先"判断，编排协议见模式 30 小节）
```

> **工作流优先**：步骤固定的任务（先做 X 再做 Y）用固定工作流，比自主循环便宜、可控、好复盘；路径不确定、必须按工具反馈多次调整才进 agentic 循环（来源：cases/codepilot-agent ADR-01）。

高级系统按需叠加：记忆（跨会话）/ 学习适应 / 目标监控 / RAG / HITL / 护栏 / 评估监控 / 优先级 / 资源预算。

## 二、模式必防的坑（选定模式后对照逐条防）

| 模式 | 必防的坑 |
|------|---------|
| 提示链 | 链过长延迟叠加；中间步骤失败要显式处理（重试/终止），别吞错 |
| 路由 | 分类器本身会错；路由规则要可测（写路由测试用例） |
| 并行化 | 聚合要处理部分失败（一个子任务挂不能全崩）；结果冲突要定义仲裁规则 |
| 反思 | 无上限循环卡死（设最大 2-3 轮）；批评者过度挑剔空转（给明确评判标准） |
| 工具使用 | schema 描述模糊→乱调；返回数据过大→上下文爆炸（截断/摘要）；循环调用要终止条件；**敏感操作标记 HITL，新工具默认 fail-closed** |
| 规划 | 计划脱离实际→死循环；必配超时 + 最大步数 + 取消机制 |
| 多智能体 | 无协调者→各自为政（用星型）；委派必须闭环（超时+反馈+兜底，见 04 事故库）；权限单调收窄；finally 确定性清场 |
| 记忆 | 无边界存储→检索噪声；记忆冲突需 correct/治理；隐私→本地 embedding 选项 |
| 学习适应 | 过拟合个别反馈；学习过程要可回滚（快照/分支） |
| 目标监控 | 目标不持久化→跨会话失忆；完成不清理→记忆库堆积 |
| 异常恢复 | 裸 except→静默全失败；无降级→依赖挂了全崩；失败无日志→无法排查 |
| HITL | fail-closed（新工具默认敏感，显式声明才绕过）；确认前不落库；防重复、防越权；只对高风险用，滥用伤体验 |
| RAG | 只做"向量检索扔给模型"→仍然幻觉；无引用→无法核验；检索质量要评估（见 03 幻觉条目 3 层检测） |
| A2A 通信 | 消息格式随意→对接爆炸；无超时→互相等待死锁 |
| 资源优化 | 无预算→账单爆炸；缓存策略不当→返回过期数据 |
| 推理增强 | 推理步骤不可验证→自信错误；长推理→token 成本上升 |
| 护栏安全 | 只靠提示词"别乱来"→可被绕过（要硬性权限）；无审计→出事无法追责 |
| 评估监控 | 无评估→"感觉能用"不可靠；无监控→生产变坏无人知 |
| 优先级 | 无限流→被打爆；重要任务被次要任务挤占 |
| 探索发现 | 探索无边界→失控乱跑（配预算/时间上限） |

## 三、生产可靠性模式（Claude Code 逆向提炼，跨场景通用）

> 这 11 个模式从 Claude Code 512K 行源码逆向而来，适用于任何生产 agent 系统，不只限于 agent 领域（也可用于 DB/K8s/微服务）。

### 21. 乐观恢复（Optimistic Recovery）
- **解决**：部分失败时能继续而不是整体放弃。
- **做法**：假设成功继续，失败时回退到已知安全点重试。

### 22. 分层降级（Layered Degradation）
- **解决**：依赖不可用时逐层降级，保住核心功能。
- **做法**：真实 LLM → mock/缓存 → 简化响应，逐层退。

### 23. 状态机 + 转换日志（State Machine + Transition Log）
- **解决**：状态流转可控、可审计、可回放。
- **做法**：显式状态机（拒绝非法转移）+ 每次转移写日志/审计事件。

### 24. 读写锁并发（Read-Write Lock Concurrency）
- **解决**：并发读写共享状态时保证一致。
- **做法**：读并发、写互斥；写时阻塞新读。

### 25. 不可变配置快照（Immutable Config Snapshot）
- **解决**：配置变更后回滚安全、可对比。
- **做法**：配置快照不可变，变更=新快照，可回滚。

### 26. 分层取消（Hierarchical Cancellation）
- **解决**：用户/系统取消任务时，级联取消所有子任务，防泄漏。
- **做法**：AbortController 3 层级联/等价机制；取消要确定性清理。

### 27. 基于能力的权限（Capability-based Security）
- **解决**：按能力而非身份授权，最小权限。
- **做法**：每个工具/操作独立授权，越权即拒。

### 28. 缓存友好分叉（Cache-Friendly Forking）
- **解决**：多 agent 分叉时共享缓存，省成本。
- **做法**：fork 前共享 prompt 缓存；隔离执行但缓存复用。

### 29. 确定性清理（Deterministic Cleanup）
- **解决**：无论成败都要清场，防资源泄漏/残留。
- **做法**：finally 清理；10 步级联清理；不依赖错误路径也执行。

### 30. 星型拓扑编排（Star Topology Orchestration）
- **解决**：多 agent 协调防混乱。
- **做法**：单一协调者 + 多个 worker，避免全互联。

**★ 星型编排协议**（多智能体设计必须配齐四件，缺一即设计未完成）：
- **拓扑三岔路**：星型默认（单一协调者裁决）/ 层级 handoff（agent 间转交，适合流水线）/ 事件驱动 mesh（松耦合大规模，需引入 A2A 协议与注册发现，复杂度大，规模真到了才用）
- **任务卡 5 字段**：目标 / 边界（含写入范围，各 worker 不重叠）/ 工具与权限档位（子 ⊆ 父）/ 验收标准 / 预算（最大步数·token·时间）
- **回传三件套**：结论 + 关键证据 + trace 引用（原始过程可追溯）；**禁全文回传**（协调者上下文被 worker 全文撑爆 = 04 坑 #A41）
- **仲裁两规则**：任务卡预分配不重叠写入范围；结论冲突由协调者裁决，worker 不互相改对方产物

> 来源：microsoft/agent-framework（生产级编排四模式 sequential/concurrent/handoff/group + 检查点/HITL）、cases/codepilot-agent ADR-05、solace-agent-mesh（mesh 岔路模式参考）。

### 31. 单调权限收窄（Monotonic Permission Narrowing）
- **解决**：权限只降不升，防权限放大攻击。
- **做法**：子代理权限 ⊆ 父代理权限，不可扩大。
