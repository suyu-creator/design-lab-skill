# 02 · 智能体设计模式库

> 按"任务确定性"选型：任务越固定越用简单模式（提示链/路由/并行），越开放越用自主模式（规划/agentic/多智能体）。
> 来源：Anthropic《Agentic Design Patterns》21 章 + Claude Code 逆向 11 个生产模式 + 社区实践。

## 一、基础模式（单一 agent 内）

### 1. Prompt Chaining 提示链
- **解决**：把复杂任务拆成固定顺序的子步骤，每步专注一件事，质量高、可调试。
- **适用**：任务可明确拆为多个顺序阶段（如：提取→翻译→校对；改写→分类→总结）。
- **结构**：`步骤1输出 → 步骤2输入 → …`，可加中途校验（不满足就重跑该步）。
- **坑**：链条过长延迟叠加；中间步骤失败要显式处理（重试/终止），不要吞掉。

### 2. Routing 路由
- **解决**：不同输入走不同处理路径，避免"一个提示词管所有"的低质量。
- **适用**：输入可明确分类（简单/复杂、中文/英文、客服/技术、不同模型成本档）。
- **结构**：分类器（LLM 或规则）→ 分发到各专用处理路径/模型。
- **变体**：模型分层路由（简单问句→Haiku/小模型，复杂→大模型），同时解决成本。
- **坑**：分类器本身会错；路由规则要可测（写路由测试用例）。

### 3. Parallelization 并行化
- **解决**：独立子任务并发执行，缩短延迟、聚合结果。
- **适用**：任务可拆成互不依赖的多个子任务（多来源检索、多维度审查）。
- **结构**：扇出（并行处理）→ 聚合（合并结果）。
- **坑**：聚合逻辑要处理部分失败（一个子任务挂了不能全崩）；结果冲突要定义仲裁规则。

### 4. Reflection 反思
- **解决**：单次生成质量不够，让模型自我批评改进。
- **适用**：代码生成、写作、方案设计等"质量可被评判"的任务。
- **结构**：生成 → 批评者指出问题 → 按反馈重写（可多轮，设上限）。
- **变体**：LLM 当评委（另一个 prompt 评判）；结构化批评清单。
- **坑**：无上限循环会卡死（设最大轮数，如 2-3 次）；批评者过度挑剔导致空转（给明确评判标准）。

### 5. Tool Use 工具使用（Function Calling）
- **解决**：让模型访问外部数据/执行动作，突破"只靠记忆"。
- **适用**：查库、查 API、算数、写文件、调外部系统等一切需要"动手"的任务。
- **结构**：工具 schema（名称+参数+描述）→ 模型决定调用 → 执行 → 结果回填 → 继续。
- **关键**：schema 描述要清晰（决定模型能否正确调用）；**敏感操作标记 HITL**；新工具默认 fail-closed。
- **坑**：工具描述模糊→乱调；返回数据过大→上下文爆炸（截断/摘要）；循环调用无终止条件。

### 6. Planning 规划
- **解决**：任务开放、需要自主决定步骤顺序（agentic 的核心）。
- **适用**：复杂多步任务、探索式任务（研究、排障、多工具协作）。
- **结构**：先规划（列出步骤）→ 逐步执行（可动态调整）→ 收尾验证。
- **变体**：ReAct（思考-行动-观察循环）；Plan-and-Execute（先计划再分步执行）；自愈规划（步骤失败重新规划）。
- **坑**：计划脱离实际→死循环；必须配超时+最大步数+取消机制（见可靠性模式）。

### 7. Multi-Agent Collaboration 多智能体协作
- **解决**：任务需要多个专长角色协作，或单一 agent 上下文溢出。
- **适用**：研究团队（搜索+分析+写作）、工程团队（架构+编码+评审）、需隔离上下文的复杂系统。
- **结构**：协调者（coordinator）编排 + 多个 worker；**推荐星型拓扑**（单一协调者，别做全互联）。
- **坑**：无协调者→各自为政；委派必须闭环（超时+反馈+兜底，见事故库）；权限要单调收窄；确定性清理（finally 清场）。

## 二、高级系统

### 8. Memory 记忆
- **解决**：跨会话保持上下文/偏好/事实，避免每次从零开始、避免记忆漂移。
- **适用**：需要记住用户偏好、项目事实、历史决策的长期智能体。
- **结构**：5 类记忆分型（见 `03` 记忆条目）+ 工具集（store/retrieve/search/correct/purge）+ 引导规则。
- **关键**：不仅给工具，还要给"何时用"——会话开始加载、结束清理+存摘要；主动治理（矛盾检测、隔离低置信）。
- **坑**：无边界存储→检索噪声；记忆冲突→需 correct/治理；隐私→本地 embedding 选项。

### 9. Learning & Adaptation 学习与适应
- **解决**：让智能体从反馈/结果中改进自身行为，而不是固定不变。
- **适用**：持续使用的产品型智能体、需要个性化适应的场景。
- **结构**：行为→反馈（显式评分/隐式结果）→ 更新规则/记忆/提示词 → 验证。
- **坑**：过度拟合个别反馈；学习过程要可回滚（快照/分支，见 memoria）。

### 10. Goal Setting & Monitoring 目标设定与监控
- **解决**：长任务不迷路，可追踪进度、可中途续接。
- **适用**：跨会话的多阶段任务、长期目标。
- **结构**：显式目标存储（GOAL 状态）→ 步骤进度跟踪 → 完成时归档/清理 → 失败时留 LESSON。
- **坑**：目标不持久化→下次会话失忆；完成不清理→记忆库堆积。

## 三、生产关注（决定能否交付）

### 11. Exception Handling & Recovery 异常处理与恢复
- **解决**：生产环境一定会出错，出错后要能恢复而不是静默失败。
- **适用**：一切上生产的智能体。
- **结构**：显式错误处理（禁止裸 except 吞错）+ 重试（带退避）+ 降级（mock/缓存/简化）+ 恢复（回到安全快照）。
- **坑**：裸 except→静默全失败；无降级→依赖挂了全崩；失败无日志→无法排查。

### 12. Human-in-the-Loop (HITL) 人在回路
- **解决**：高风险/不可逆操作需人工确认，防止模型擅自执行。
- **适用**：退款、删除、发送消息、写生产数据、任何敏感/高成本动作。
- **结构**：工具声明 sensitive → 模型发起请求 → 前端/UI 弹窗确认 → 确认后才执行 → 记录审计。
- **关键**：fail-closed（新工具默认敏感，显式声明才绕过）；确认前不落库；防重复；防越权。
- **坑**：确认被绕过→风险操作直通；HITL 频繁→体验差（只对高风险用）。

### 13. Knowledge Retrieval (RAG) 知识检索
- **解决**：让模型基于自有知识库回答，缓解幻觉、回答可溯源。
- **适用**：客服知识库、文档问答、需引用来源的场景。
- **结构**：摄取（切块→embedding→向量库）→ 检索（混合检索+重排）→ 生成（带引用）。
- **进阶**（幻觉重点防线，见 `03` 幻觉条目）：3 层幻觉检测 + 置信度阈值 + 精炼循环。
- **坑**：只做"向量检索就扔给模型"→仍然幻觉；无引用→无法核验；检索不相关→答非所问（要评估检索质量）。

## 四、多智能体架构

### 14. Inter-Agent Communication (A2A)
- **解决**：多智能体间用标准协议通信，避免耦合死锁。
- **适用**：跨系统/跨组织的智能体协作。
- **结构**：标准消息契约（任务/状态/结果）+ 权限边界。
- **坑**：消息格式随意→对接爆炸；无超时→互相等待死锁。

### 15. Resource-Aware Optimization 资源感知优化
- **解决**：控制 token/成本/延迟，别让智能体"想怎么花就怎么花"。
- **适用**：高用量、多用户、按量计费场景。
- **结构**：预算上限 + 模型分层 + 结果缓存 + 优先级调度。
- **坑**：无预算→账单爆炸；缓存策略不当→返回过期数据。

### 16. Reasoning Techniques 推理增强
- **解决**：复杂逻辑问题单次生成不够准。
- **适用**：数学、代码、逻辑推理、多步因果分析。
- **结构**：显式推理步骤（CoT）、自我验证、或分步 agentic 推理。
- **坑**：推理步骤不可验证→自信错误；长推理→token 成本上升。

### 17. Guardrails & Safety 护栏与安全
- **解决**：防注入、防越权、防有害输出、防工具滥用。
- **适用**：一切暴露给用户/外部系统的智能体（安全必须内置，不是后期补）。
- **结构**：输入校验（schema）→ 权限控制（fail-closed + 单调收窄）→ 输出过滤 → 审计日志 → 对抗测试。
- **坑**：只依赖提示词"别乱来"→ 可被绕过（要用硬性权限）；无审计→出事无法追责。

### 18. Evaluation & Monitoring 评估与监控
- **解决**：怎么知道智能体"够好了"、上线后有没有变坏。
- **适用**：一切要交付的智能体（交付的前提是能度量）。
- **结构**：离线评估集（黄金用例+指标）+ 在线监控（日志/指标/trace/告警）。
- **指标**：检索质量（Precision@k/MRR/NDCG）+ 生成质量（Faithfulness/Relevancy，LLM 当评委）。
- **坑**：无评估→"感觉能用"不可靠；无监控→生产变坏无人知。

### 19. Prioritization 优先级
- **解决**：多请求/多任务并发时保重要、丢次要，避免过载。
- **适用**：并发用户多、任务队列长。
- **结构**：任务分级（关键/普通/后台）→ 限流 + 排队 → 过载降级。
- **坑**：无限流→被打爆；重要任务被次要任务挤占。

### 20. Exploration & Discovery 探索与发现
- **解决**：让智能体主动探索新方案/新信息，而不是只按老路子走。
- **适用**：研究、竞品分析、创新方案类任务。
- **结构**：多路并行探索 → 证据收集 → 收敛筛选。
- **坑**：探索无边界→失控乱跑（配预算/时间上限）。

## 五、生产可靠性模式（Claude Code 逆向提炼，跨场景通用）

> 这 11 个模式从 Claude Code 512K 行源码逆向而来，适用于任何生产 agent 系统，不只限于 agent 领域（也可用于 DB/K8s/微服务）。

### 21. 乐观恢复（Optimistic Recovery）
- **解决**：部分失败时能继续而不是整体放弃。
- **做法**：假设成功继续，失败时回退到已知安全点重试。

### 22. 分层降级（Layered Degradation）
- **解决**：依赖不可用时逐层降级，保住核心功能。
- **做法**：真实 LLM → mock/缓存 → 简化响应，逐层退。

### 23. 状态机 + 转换日志（State Machine + Transition Log）
- **解决**：状态流转可控、可审计、可回放。
- **做法**：显式状态机（拒绝非法转移）+ 每次转移写日志/审计事件。

### 24. 读写锁并发（Read-Write Lock Concurrency）
- **解决**：并发读写共享状态时保证一致。
- **做法**：读并发、写互斥；写时阻塞新读。

### 25. 不可变配置快照（Immutable Config Snapshot）
- **解决**：配置变更后回滚安全、可对比。
- **做法**：配置快照不可变，变更=新快照，可回滚。

### 26. 分层取消（Hierarchical Cancellation）
- **解决**：用户/系统取消任务时，级联取消所有子任务，防泄漏。
- **做法**：AbortController 3 层级联/等价机制；取消要确定性清理。

### 27. 基于能力的权限（Capability-based Security）
- **解决**：按能力而非身份授权，最小权限。
- **做法**：每个工具/操作独立授权，越权即拒。

### 28. 缓存友好分叉（Cache-Friendly Forking）
- **解决**：多 agent 分叉时共享缓存，省成本。
- **做法**：fork 前共享 prompt 缓存；隔离执行但缓存复用。

### 29. 确定性清理（Deterministic Cleanup）
- **解决**：无论成败都要清场，防资源泄漏/残留。
- **做法**：finally 清理；10 步级联清理；不依赖错误路径也执行。

### 30. 星型拓扑编排（Star Topology Orchestration）
- **解决**：多 agent 协调防混乱。
- **做法**：单一协调者 + 多个 worker，避免全互联。

### 31. 单调权限收窄（Monotonic Permission Narrowing）
- **解决**：权限只降不升，防权限放大攻击。
- **做法**：子代理权限 ⊆ 父代理权限，不可扩大。
