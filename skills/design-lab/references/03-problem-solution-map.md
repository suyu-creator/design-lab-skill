# Part 1 · 架构问题（按"系统在乎什么"查）

先问：**这段方案碰了哪些容易出事故的东西？** 再挑对应组查：

```
碰钱 / 库存          ──▶ 查 A 一致性（幂等、并发、超卖）
调用外部 / 高并发     ──▶ 查 B 韧性（超时、重试、降级）
用了 Redis / MQ      ──▶ 查 B2 缓存与消息（穿透、击穿、雪崩、积压）
面向海量用户          ──▶ 查 C 规模（热点、扇出、分页）
处理用户数据 / 多租户  ──▶ 查 D 安全（越权、隔离、注入）
用了大模型            ──▶ 必查 E AI 特有（兜底、成本、幻觉、eval）
```

## A. 一致性（碰钱 / 库存）

| 担心的问题 | 方案 | 参考 |
|---|---|---|
| 重复请求/超时重发重复扣款 | **幂等**：给操作一个幂等键，消费端去重表，同键再来直接跳过 | 04#exactly-once |
| 跨服务/跨库写入中途失败 | **Saga**（补偿）/ **Outbox**（先写本地事务+发事件） | 08 |
| 哪些该强一致、哪些可最终一致 | **先问数据配得上多强**：ATM 余额→线性一致；评论→因果一致；点赞数→最终一致 | 01 心法 |
| 并发改同一数据超卖/丢更新 | 原子扣减（条件更新）+ 状态机防非法转移 | 05 一致性组 |
| 跨进程互斥（多实例同时干一件事） | 优先 DB 原子条件更新/唯一约束；用 Redis 锁必须处理**锁过期与续期**，跨实例强一致慎用 RedLock（争议大） | 04#20、06 活源 |

**关键认知**：强一致不是更好，而是**更贵**。每升一档都在付延迟和可用性的账单。把宝贵强一致配额花在真正会出事的地方。

## B. 韧性（调外部 / 高并发）

| 担心的问题 | 方案 | 参考 |
|---|---|---|
| 外部调用无限等待 | **每个调用设超时**（AI 最常漏的就是裸调用） | 04#级联失败 |
| 失败重试把下游打死 | **指数退避 + 抖动 + 重试预算 + 幂等前提**，四样缺一不可 | 04#裸重试 |
| 依赖挂了整个拖死 | **熔断**（fail fast，半开试探恢复）+ **降级**（返回兜底/缓存/默认值） | 04#级联失败 |
| 一个慢依赖吸干整个资源池 | **舱壁**（独立线程池）+ 超时预算逐层递减 | 04#级联失败 |
| 过载时来者不拒全崩 | **降载**：超容量立刻返回 429/503，保住放进来的请求被好好服务 | 04 |

**核心判断**：慢比宕机更致命——宕机快速失败立刻还资源，慢让请求抱着资源一点点死掉并顺着调用链传染。韧性工程一半功夫是**不让慢传播**。

## B2. 缓存与消息（用了 Redis / MQ 必查）

| 担心的问题 | 方案 | 参考 |
|---|---|---|
| 查不存在的 key 每次都打穿到 DB | **缓存穿透**：空值缓存短 TTL / 布隆过滤器挡一层 | 04#20 |
| 热点 key 过期瞬间大量请求同时回源 | **缓存击穿**：互斥锁重建 / 逻辑过期 / 提前预热 | 04#20 |
| 大批 key 同一时刻集中过期 | **缓存雪崩**：TTL 基准 + 随机抖动（如 30min±10min），别全用一个过期时间 | 04#20 |
| 改了 DB 用户还看到旧数据 | cache-aside + **先更库后删缓存**；一致性要求高才上 binlog 订阅失效 | 04#19 |
| Redis 挂了全站跟着崩 | 缓存必须是**可丢的**（丢了变慢不变错）；降级直接回源 + 回源限流 | 04#18 |
| 消息重复投递 / 队列积压 / 死信 | 消费端幂等 + 积压长度告警 + 死信有人工修复入口 | 04#22、A 组幂等 |
| 消息丢了没人知道（生产/存储/消费确认三段任一断裂） | 三段各自确认：生产者确认回执、broker 持久化、消费手动 ACK | 06 活源 tutorial/29 |
| 消息乱序（同一订单先"取消"后"支付"被颠倒处理） | 需要有序的场景按**业务键分区**（同 key 进同队列），消费端状态机拒绝非法转移 | 06 活源 tutorial/29 |
| 事件设计混乱（把"命令"当"事件"发，下游回滚不了） | **命令=请对方做事（要成功失败），事件=告知已发生（订阅方自理）**；事实不可回滚，发事件前先确认已提交 | 06 活源 tutorial/29 |
| 单 key 几十 MB / 热点 key 打爆单节点 | 拆小 key；热 key 本地缓存 + 副本分担 | 04#21 |
| 本地缓存多实例各改各的 | 只放缓变数据（配置/字典）+ 版本号广播失效；快变数据走分布式缓存 | 04#23 |

**核心判断**：缓存的价值在"丢了变慢、不改结果"。缓存丢了系统会**变错**，说明把业务状态偷偷放进缓存了。深挖活源：`06` 活源表「缓存与消息」。

## C. 规模（海量用户）

| 担心的问题 | 方案 | 参考 |
|---|---|---|
| 热 key / 热分区打爆单点 | 识别热点（明星用户/爆款商品），一致性哈希 + 副本分担 | 06 |
| N+1 查询 / 扇出放大 | 循环里查库改批量；扇出用事件驱动/队列异步 | 01#消息队列 |
| 列表接口一把捞几百万行 | **分页 + 上限**硬约束 | 05 规模组 |
| 一条慢路径拖累整体 | 盯 **P99 而非 P50**；缓存/异步化隔离慢路径 | 04#尾延迟 |
| 读写分离后读到旧数据（主从延迟） | 设计期先答"这业务容忍读旧多久"；不能容忍的读走主库（写后读一致）或等同步完成 | 06 活源 tutorial/28 |

**核心判断**：从用户 1 万涨到 1 亿，第一个瓶颈在哪？先算信封估算（08），别等被成功撑爆才布局。

## D. 安全（用户数据 / 多租户）

| 担心的问题 | 方案 | 参考 |
|---|---|---|
| SQL / 命令注入 | 参数化查询 + 输入校验（schema） | 05 安全组 |
| 改个 ID 看别人数据（越权） | **每个接口校验用户是否有权**做这件事，不靠客户端声称 | 05 安全组 |
| 跨租户读到数据 | 查询强制按租户过滤 + 租户隔离（DB/表/行级） | 05 安全组 |
| 密钥硬编码 / 进日志 | 环境变量/密钥管理器 + 日志脱敏 | 05 安全组 |
| 提示注入（AI 系统） | 检索结果/工具返回/用户上传**全部当不可信输入** | 05 AI 组 |

**核心判断**：威胁建模 + 爆炸半径控制 + 零信任。安全内置，不是后期补。

## E. AI 特有（用了大模型必查）

| 担心的问题 | 方案 | 参考 |
|---|---|---|
| 模型输出不对/不稳定无兜底 | 非确定性兜底 + 碰副作用前护栏/人审 | 05 AI 组 |
| 自主循环烧钱（agent 原地打转） | **步数/成本/超时硬上限** = 降载+熔断在 AI 时代的形态 | 04#自主循环 |
| RAG 检索幻觉、答非所问 | 混合检索+重排 + 强制引用溯源 | 05 AI 组 |
| 换模型/改提示后悄悄变差 | **eval 当 CI 门禁**，把"够好"写进架构 | 05 AI 组 |

**核心判断**：LLM 把一层新不确定性叠在系统原本的不确定性之上（会跑偏/幻觉/陷入循环）。AI 原生系统不是更不需要韧性，而是**更需要新形态的韧性**——给自主循环装刹车。

# Part 2 · 智能体问题（agent 专属，按症状查）

> 需求涉及智能体时才需要查这部分。

## 1. LLM 幻觉（最常问）
**症状**：模型自信地编造事实/数据/引用；"一本正经胡说八道"。
**具体方案（按严重程度递进）**：
1. **提示层**：system prompt 明确"不知道就说不知道，不要猜测"（"don't fake it"原则）；要求"只基于提供的资料回答"。
2. **RAG + 引用溯源**：基于知识库回答，每条回答带 `[来源 id]`，可点击核对。
3. **3 层幻觉检测**（Pari2003，幻觉↓97%）：
   - Layer 1：把答案拆成原子声明，逐条与来源做 embedding 相似度
   - Layer 2：NLI 蕴含判断——来源是"支持"还是"矛盾"这条声明
   - Layer 3：关键数字/名字是否真的出现在来源文本中
4. **置信度阈值 + 精炼循环**：置信度 < 0.7 → 精炼器重写坏声明 → 再检测（最多 2 轮）。
5. **输出附证据**：`confidence_score` + 逐声明 `claim_report` + 可追溯引用。
6. **评估防线**：评估集注入幻觉声明（如"爱因斯坦 1905 年发明 RAG"）验证拦截器能抓到。
> 参考：`02` 模式 13（RAG）、`07` 模板、`04` 坑 #A11。

## 2. 工具滥用 / 越权 / 危险操作
**症状**：模型乱调工具、执行越权/破坏性操作、被 prompt 注入诱导。
**具体方案**：
1. **fail-closed 权限**：新工具默认敏感（sensitive=True），显式声明才绕过。
2. **敏感操作 HITL**：退款/删除/发送/写生产数据等 → 弹窗让用户确认 → 确认后才执行 → 记审计。
3. **基于能力的权限**：每个工具独立授权，最小权限（02 模式 27）。
4. **单调权限收窄**：子代理权限 ⊆ 父代理（02 模式 31）。
5. **对抗测试**：用 ASTRA 式攻击集（prompt 注入/越权/诱骗）压测护栏。
> 参考：`02` 模式 5/17、`09` 护栏节。

## 3. 多智能体失控
**症状**：多个 agent 各干各的、任务重复/冲突、互相等待死锁、一个挂全崩。
**具体方案**：
1. **星型拓扑**：单一协调者 + 多个 worker，别做全互联（02 模式 30）。
2. **委派闭环**：每次委派带 超时 + 反馈 + 兜底（04 坑 #A01）。
3. **确定性清理**：finally 清场，失败也回收资源（02 模式 29）。
4. **A2A 契约**：消息格式标准化（任务/状态/结果）+ 权限边界。
5. **监护**：协调者进程要有 watchdog + 告警 + 自重启（04 坑 #A07）。
6. **回传协议**：worker 只回 结论 + 关键证据 + trace 引用，禁全文回传（04 坑 #A41，02 模式 30）。
7. **仲裁规则**：写入范围预分配不重叠；结论冲突协调者裁决（04 坑 #A42）。
> 参考：`02` 模式 7/14/30、`04` 坑 #A01/#A03/#A41/#A42。

## 4. 上下文爆炸 / 成本失控
**症状**：上下文塞满工具返回、token 账单飙升、长任务越跑越贵。
**具体方案**：
1. **静态/动态 prompt 分离**：不变内容放前面（利于缓存），变化内容独立。
2. **工具返回截断/摘要**：大返回只回填关键信息。
3. **模型分层路由**：简单任务→小模型（Haiku），复杂→大模型（Opus），成本差 3-10x。
4. **预算上限 + 优先级**：token 预算封顶，高价值任务优先（02 模式 15/19）。
5. **缓存**：重复查询/常见答案走缓存。
> 参考：`02` 模式 2/15/19、`09` 监控节。

## 5. 卡死 / 无限循环 / 空转
**症状**：agent 反复重试同一动作、反思空转、工具调用死循环。
**具体方案**：
1. **分层取消**：用户取消时级联取消所有子任务（02 模式 26）。
2. **超时 + 最大步数**：单轮/总循环设上限（如最大 10 步、反思最多 2-3 轮）。
3. **状态机 + 转换日志**：状态流转显式化，非法转移拒绝，可回放定位（02 模式 23）。
4. **乐观恢复**：失败回退到已知安全点，不原地空转（02 模式 21）。
> 参考：`02` 模式 4/6/11、`09` 异常恢复节。

## 6. 不可复现 / 难测试
**症状**：真实 LLM 输出不确定，测试没法跑、跑不过、覆盖不了。
**具体方案**：
1. **双轨 Agent**：mock 规则引擎（确定性、可断言）+ 真实 LLM（实际效果），同一接口两套实现。
2. **评估集**：黄金用例（覆盖 BDD 场景）+ 断言指标。
3. **协议契约测试**：工具 schema 恒定，测"schema 不变、参数合法"。
4. **状态机全流转测试**：合法流转全测 + 非法转移拒绝测试。
> 参考：`09` 评估节、`07` 测试模板。

## 7. 记忆漂移 / 无边界
**症状**：记忆库塞满噪声、旧事实和新的冲突、检索不到该记的。
**具体方案**（memoria 方案）：
1. **5 类记忆分型**：semantic（事实）/ profile（偏好）/ procedural（流程）/ working（临时）/ episodic（会话摘要）。
2. **引导规则**（关键）：会话开始 retrieve 加载上下文 + search 查活跃目标；中途偏好→store、纠正→correct、话题切换→retrieve；结束 purge 工作记忆 + store episodic 摘要。
3. **自我治理**：自动检测矛盾（consolidate）+ 隔离低置信记忆（governance）+ 审计追踪。
4. **版本化**：快照/分支/合并/回滚——高风险记忆实验隔离（branch），失败可 rollback。
> 参考：`02` 模式 8/9、`04` 坑 #A21。

## 8. 安全 / 注入 / 数据泄露
**症状**：prompt 注入劫持、越权访问、敏感数据外泄、恶意输出。
**具体方案**：
1. **输入校验**：所有外部输入过 schema 校验，fail fast。
2. **权限 fail-closed** + 单调收窄（见问题 2）。
3. **输出过滤**：敏感内容过滤、PII 脱敏。
4. **审计日志**：所有工具调用/状态变更落审计，可追责。
5. **对抗测试**：注入/越权攻击集压测（ASTRA 140 次攻击）。
6. **密钥管理**：不硬编码密钥，走环境变量/密钥管理器；泄露即轮换。
> 参考：`02` 模式 17、`09` 护栏节。

## 9. 静默失败
**症状**：某步悄悄失败但流程"看似正常"，事后才发现结果错/缺。
**具体方案**：
1. **禁止裸 except 吞错**：失败必须显式记录/上报（04 坑 #A05）。
2. **产物注册**：系统必须注册自己的产物（artifact registry），可核对完整性。
3. **负面证据也是数据**：失败结果要保留可查，不覆盖。
4. **委派闭环**（见问题 3）。
> 参考：`04` 坑 #A05/#A06。

## 10. 单点故障
**症状**：某个进程/依赖挂了，整个系统停摆。
**具体方案**：
1. **关键进程 watchdog**：守护 + 告警 + 自动重启。
2. **分层降级**：依赖挂了逐层退（真实→mock/缓存→简化），保核心（02 模式 22）。
3. **冗余**：关键路径多实例/备节点。
> 参考：`04` 坑 #A07。

## 11. 配置变更级联崩溃
**症状**：改模型/endpoint/参数后，全系统行为突变甚至崩溃。
**具体方案**：
1. **不可变配置快照**：配置=不可变快照，变更=新快照，可回滚可对比（02 模式 25）。
2. **变更后健康验证**：任何配置变更后跑健康检查 + 冒烟测试。
3. **灰度**：先小流量验证再全量。
> 参考：`04` 坑 #A08。

## 12. 知识库检索不准
**症状**：RAG 检索到不相关内容、答非所问、找不到该有的。
**具体方案**：
1. **混合检索**：向量（语义）+ 关键词 BM25（精确）+ 图增强（实体关系），RRF 融合。
2. **父子切块**：小块（~256tok，检索精准）+ 大块（~1024tok，上下文完整），小块命中→取父块回答。
3. **LLM 重排**：检索 top-k 后让 LLM 选最相关的 top-5。
4. **评估检索质量**：Context Precision@k / Recall@k / MRR / NDCG / Hit Rate@k。
> 参考：`02` 模式 13、`04` 坑 #A12。

## 13. 延迟 / 性能差
**症状**：响应慢、流式卡顿、并发打不上去。
**具体方案**：
1. **并行化**：独立子任务并发，别串行（02 模式 3）。
2. **流式输出**：SSE/流式逐字返回，首字延迟优先。
3. **缓存 + 分层模型**（见问题 4）。
4. **资源感知**：队列 + 优先级 + 限流（02 模式 15/19）。
> 参考：`02` 模式 3/15/19。

## 14. 隐私 / 合规
**症状**：用户数据/公司机密进模型、跨境传输、无法删除。
**具体方案**：
1. **本地模型/本地 embedding**：数据不出机器。
2. **数据最小化**：只传必要上下文，PII 脱敏。
3. **可删除**：用户数据可删、记忆可 purge。
4. **审计 + 合规标注**：谁在什么时间碰了什么数据。
> 参考：`02` 模式 8、`09` 监控节。
