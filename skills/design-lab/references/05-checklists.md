# 05 · 检查清单（合并：架构审查 5 组 + 智能体设计检查 + 评审标准 + 交付门禁）

> 审架构方案 / 审智能体设计 / 审 AI 产出时逐项自查。**不是每条都要查**——按"系统在乎什么"挑相关组。任何 CRITICAL 未过 = 不能交付。

## 一、架构审查清单（按质量属性分 5 组）

> AI 产出默认缺一半：没超时、没幂等、没降级、没分片、没防注入。因为它优化能跑通、训练数据偏 demo、又不知道你的非功能需求。**对付 AI 靠固定清单逐条机械过一遍，不靠仔细看——它每次漏的几乎是同一批东西。**

### A. 一致性组（碰钱 / 库存）
- [ ] **幂等**：重复请求 / 超时重发会不会重复扣款、重复下单？有幂等键吗？
- [ ] **跨服务一致性**：跨了多个服务/库的写，用 Saga / Outbox 了吗？中途失败怎么补偿？
- [ ] **事务边界**：哪些必须强一致（钱/库存），哪些可最终一致？有没有把该强一致的做成最终一致？
- [ ] **并发**：两个请求同时改一条数据会怎样？有没有超卖 / 丢更新？

### B. 韧性组（调外部 / 高并发）
- [ ] **超时**：每个外部调用（DB / 第三方 / 模型 API）都设超时了吗？（AI 最常漏的就是裸调用）
- [ ] **重试**：失败重试了吗？是**指数退避 + 抖动**还是无脑重试？重试的操作幂等吗（否则放大事故）？
- [ ] **熔断 / 降级**：依赖挂了，是整个拖死，还是能熔断 + 降级返回兜底？
- [ ] **资源上限**：有没有无界队列 / 无上限并发 / 无超时的循环（会 OOM 或失控）？

### C. 规模组（海量用户）
- [ ] **热点**：有没有热 key / 热分区？某个明星用户 / 爆款商品会不会打爆单点？
- [ ] **N+1 与扇出**：循环里查库？一次请求扇出成 N 次下游调用？
- [ ] **分页 / 上限**：列表接口有没有分页？会不会一把捞出几百万行？
- [ ] **尾延迟**：P99 而非 P50；有没有一条慢路径拖累整体？

### D. 安全组（用户数据 / 多租户）
- [ ] **输入校验**：外部输入都校验了吗？SQL / 命令注入？
- [ ] **鉴权与越权**：每个接口都校验这个用户是否**有权**做这件事吗？能不能改个 ID 就看到别人的数据（越权）？
- [ ] **多租户隔离**：查询强制按租户过滤了吗？会不会跨租户读到数据？
- [ ] **密钥**：有没有把 API key / 密码硬编码进代码 / 日志？
- [ ] **提示注入（AI 系统）**：检索结果 / 工具返回 / 用户上传当不可信输入了吗？

### E. AI 特有组（用了大模型必查）
- [ ] **非确定性兜底**：模型输出不对 / 不稳定时有兜底吗？碰副作用前有护栏 / 人审吗？
- [ ] **成本上限**：每次调用 / 每个任务有 token、步数、预算上限吗（防失控烧钱 / 自主循环）？
- [ ] **检索 / 幻觉**：RAG 检索质量盯了吗？答案强制基于资料 + 给引用了吗？
- [ ] **可评测**：有 eval 防止换模型 / 改提示后悄悄退化吗？

## 二、怎么用（别变成打勾仪式）

先问"这段方案碰了哪些容易出事故的东西？"，再挑相关组逐条追问：

```
碰钱 / 库存          ──▶ A 一致性
调用外部 / 高并发     ──▶ B 韧性
面向海量用户          ──▶ C 规模
处理用户数据 / 多租户  ──▶ D 安全
用了大模型            ──▶ 必查 E
```

- **清单是提问模板，不是打勾仪式**：对着方案/代码挑相关几条逐条追问"这里怎么处理"——答不上来或答得心虚的地方，就是埋的雷。
- **可喂回 AI 自审**：把清单写进 prompt 让 AI 产出后逐条自查，它被明确要求核对时能自己补一大半。
- **但人做最终判断**：AI 能抓"忘了超时"这种机械疏漏，判断不了"这个最终一致性在这里能不能接受"这种需要业务上下文和取舍的事——**判断不可外包**。

## 三、智能体设计检查清单（随 agent-flow 四步走）

### 需求与场景（Step 1 澄清 + 2.1 BDD）
- [ ] 智能体一句话定位清晰（做什么/给谁/在哪跑）
- [ ] 用户/场景/规模/技术栈已澄清
- [ ] BDD 场景覆盖：主流程 + 异常 + 边界（至少各 1 个）
- [ ] 用户确认过场景

### 模式选型（2.2）
- [ ] 已按任务确定性选型（固定→链/路由/并行；开放→规划/agentic；多角色→多智能体）
- [ ] 给出 ≥1 个候选 + 权衡，用户已选
- [ ] 复用优先：已搜过现成实现，覆盖 <80% 才从零写

### 结构设计（2.3）
- [ ] 优先单智能体（无拆分必要不硬拆多）
- [ ] 工具集明确：每个工具用途 + 是否敏感（HITL）
- [ ] 记忆方案明确（不需要 / 5 类分型中的哪些）
- [ ] 权限 fail-closed + 单调收窄
- [ ] 形态落地明确（Claude Code skill / 独立骨架）

### 提示词（2.3）
- [ ] 角色/目标/工具清单/行为边界齐全
- [ ] "不知道就说不知道"已写入
- [ ] 输出格式约束 + few-shot 示例

### 测试（2.4）
- [ ] 评估集覆盖 BDD 场景 + 对抗用例
- [ ] 双轨（mock 确定性 + real 契约）已规划
- [ ] 状态机/权限/工具协议测试已规划

### 交付（Step 6 闭环）
- [ ] 走完 `09-delivery.md` 发布检查清单
- [ ] 复用清单（引用了哪些现成项目/库）已列

## 四、评审标准（按严重级别）

| 级别 | 含义 | 行动 |
|------|------|------|
| **CRITICAL** | 安全漏洞 / 数据丢失 / 静默失败风险 | **BLOCK** — 必须修才能交付 |
| **HIGH** | 明显 bug / 关键路径缺失 | **WARN** — 应修再交付 |
| **MEDIUM** | 可维护性问题 | 考虑修 |
| **LOW** | 风格/细节 | 可选 |

### 必查 CRITICAL 项（命中任何一条即 BLOCK）
- [ ] 外部调用无超时 / 裸调用无重试策略
- [ ] 碰钱/库存无幂等（重复扣款/超卖风险）
- [ ] 依赖无熔断降级（一个慢依赖可拖垮全站）
- [ ] 越权操作无 403 / 多租户无隔离 / 权限提权漏洞
- [ ] 密钥硬编码 / 提示注入未当不可信输入
- [ ] 自主循环（agent）无步数/成本上限
- [ ] 敏感工具未标记 HITL / fail-closed
- [ ] 裸 except 吞错 / 静默失败路径
- [ ] 无评估集就宣称"可交付"
- [ ] 无异常恢复（超时/降级/取消）就上线

## 五、交付门禁（全部通过才算完成）

1. 信封估算已做（量级正确，不是拍脑袋）
2. 组件/数据流/选型都落到具体（不是概念名词）
3. 韧性设计逐项过：超时/重试/熔断/降级/隔离
4. 关键选型写了 ADR（08：为什么 / 放弃了什么）
5. 给了演进路线（何时升级 / 何时过度设计）
6. 审查清单挑相关组过了，无 CRITICAL 项
7. 智能体部分：评估集通过（含对抗用例）+ 双轨测试通过 + 护栏齐全 + HITL 正确配置 + 可观测性接入（日志/指标/trace/告警）
8. 复用清单给出（参考了哪些模板 / 现成系统）
9. 职责边界遵守（只做判断与设计，未越权写业务代码）
