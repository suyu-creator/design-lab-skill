# Part 1 · 架构坑（#01-#17）

## A. 过度设计

- **#01 微服务滥用**（[文献]）：组织没大、没独立部署需求、没平台能力就拆微服务，函数调用变网络调用，引入整座分布式复杂度大山。→ 三个前提同时满足才拆；**默认模块化单体**，痛在明确某处再拆。
- **#02 过早 CQRS / 插件化**（[文献]）：读写压力差不多、没扩展需求就上重武器，复杂度翻倍。→ 绝大多数系统不需要 CQRS；没让外人扩展需求的系统别搞插件化。
- **#03 拿成熟期架构套 MVP**（[文献]）：用户 100 人就按 1 亿人设计，过度设计是病。→ 从简单开始、被痛驱动地演进；给演进路线而不是一步到位。

## B. 分布式硬骨头

- **#04 忽略部分失败 / 灰色失败**（[文献]）：默认跨网络调用会成功；分不清对方是死还是慢，超时只是猜测。→ 默认每次调用可能失败/超时/重复，先问"这样我的系统会怎样"；超时猜短了误杀慢节点引发重试雪上加霜，猜长了恢复迟钝。
- **#05 追求 exactly-once 投递**（[文献]）：传递层根本做不到恰好一次。→ **at-least-once + 消费端幂等 = 效果上的恰好一次**；用幂等键 + 去重表，别在传输层追求幻觉。
- **#06 把共识当数据库用**（[文献]）：每条业务写入都塞进 Raft 共识组，为根本不需要的全局唯一顺序付昂贵延迟与吞吐。→ 共识只用于选主/元数据/锁/复制日志；业务数据该分片分片、该最终一致最终一致。
- **#07 一致性一刀切**（[文献]）：所有数据都强一致，付不起账单；或全最终一致，钱算错。→ 先问数据配得上多强：ATM 线性、评论因果、点赞最终；**PACELC**：不分区的 99% 时间也在拿延迟换一致性，这是天天在付的水电费。

## C. 韧性缺失

- **#08 级联失败：慢依赖不设防**（[文献]）：一个慢 DB → B 线程池耗尽 → A 超时 → 客户端重试风暴 → 全站 503。慢比宕机更致命，慢让请求抱着资源一点点死掉并顺着调用链传染。→ 超时预算逐层递减（总时限 3s → 网关 2.5s → A 1.5s → DB 0.8s）；熔断 fail fast；舱壁分池；降载主动丢一部分保整体。
- **#09 裸重试 `retry(3)`**（[文献]）：失败立刻重试、无退避无抖动，重试风暴把刚恢复的下游反复打死。→ **指数退避 + 抖动 + 重试预算 + 幂等前提**，四样缺一不可。抖动一行代码换数量级稳定性。
- **#10 共享资源池一损俱损**（[文献]）：所有下游调用共用一个线程池，慢依赖吸干整个池。→ 舱壁分池（支付 20 线程/推荐 10 线程互不侵占）；cell-based 复制整个服务栈；shuffle sharding 随机组合摊薄连坐。
- **#11 追求 100% 可靠**（[文献]）：永远不敢发布、不敢实验，迭代归零。→ **错误预算**：SLO=99.9%，0.1% 是允许出错的额度，预算还有剩大胆上新，烧光冻结上新全员搞稳定性。
- **#12 容灾预案没演练**（[文献]）：熔断/降级/failover 恰恰是平时跑得最少、最易悄悄坏掉的代码路径，真出事才发现降级开关三个月前就失灵了。→ **混沌工程**：主动可控注入故障证明韧性（前提：有监控/爆炸半径/一键中止，没有护栏就注故障不叫混沌叫事故）。
- **#13 度量盯 MTBF 不看 MTTR**（[文献]）：把 MTBF 从 30 天提到 60 天花钱指数级，且总有意外。→ 转向 **MTTR**：坏了多久能恢复，靠自动检测/切换/隔离爆炸半径，可用性杠杆全在这端。

## D. 交付与演进

- **#14 AI 只写 happy path**（[文献]）：AI 产出默认没超时、没幂等、没降级、没分片、没防注入，demo 秒跑上生产玻璃脆。→ 用 05 审查清单逐条补问；把清单喂回 AI 自审，但碰钱/安全人做最终判断。
- **#15 变更无爆炸半径控制**（[事故]）：错误命令/坏正则全球一次性推送，局部 bug 放大成全局灾难。→ 危险操作装下限保护护栏 + 金丝雀/灰度发布 + 变更可一键回滚。
- **#16 恢复工具依赖故障系统**（[事故]）：出事后连恢复工具/门禁都连不上（都跑在故障系统上）。→ 恢复工具必须独立于被恢复系统（独立网络/通道）。
- **#17 自动化按规则闯大祸**（[事故]）：自动故障切换在分区时按配置正确执行，却切进灾难性拓扑。→ 自动化越强越要想清它在极端情况下会做什么决定；为单节点设计的自动机制要考虑区域级分区场景。

## 事故档案（架构踩坑实证）

- **GitHub 43 秒分区、乱了 24h（2018-10-21）**：例行换光纤设备导致美东数据中心断联 43 秒。Orchestrator 按 Raft 共识判定美东主库不可用，自动把主库切到美西；43 秒后网络恢复，两岸都收过写入成了各持对方没有数据的分叉集群，只能人工小心修复，服务降级 24h11m。事后头号整改：禁止 Orchestrator 跨区域提升主库。→ 对应 #17、#04。
- **AWS S3 大故障（2017-02-28）**：工程师按排查手册执行命令，参数输错导致下线服务器远多于预期，误伤支撑整个区域对象元数据索引的子系统，大半个互联网瘫痪约 4h。→ 对应 #15（手抖是常态，危险操作要装下限保护护栏）。
- **Meta 全球宕机 6h（2021-10-04）**：一条想评估骨干网容量的命令意外撤下全部骨干网连接，审计工具 bug 没拦住。DNS 检测到失联主动撤回 BGP 路由通告，全世界找不到 Facebook 的 DNS。雪上加霜：内部工具、门禁系统都依赖这套网络，工程师连机房都进不去。→ 对应 #15、#16（级联失败 + 恢复工具循环依赖）。
- **Cloudflare 全球故障 27min（2019-07-02）**：一条 WAF 正则触发灾难性回溯，CPU 爆炸式增长，规则无灰度一次性推送全球所有边缘服务器，全球处理流量的 CPU 全部打满。→ 对应 #15（资源耗尽 + 变更无爆炸半径控制）。

> 三个共同剧本：一个微小局部触发，顺着资源耗尽、自动化连锁、全局推送这些放大器，炸成全局灾难。韧性工程就是在每个放大器上装闸：隔离、熔断、降载、爆炸半径控制、灰度发布。

# Part 2 · 智能体坑（#A01-#A38）

## A. 委派与协作

- **#A01 未验证能力就委派**（[事故]）：把关键任务委派给没测过的 agent，它静默失败 14 小时没人发现。→ 委派必须闭环：超时 + 反馈 + 兜底；新 agent 先测再用。
- **#A02 委派后撒手不管**（[事故]）：发任务给别的 agent 就以为完成了。→ 每次委派带超时、结果确认、失败回退路径。
- **#A03 无协调者的多 agent**（[逆向]）：多 agent 全互联、各自为政。→ 用星型拓扑：单一协调者 + worker。
- **#A04 多 agent 死锁**（[文献]）：两个 agent 互相等待对方结果。→ A2A 消息带超时；无结果按超时处理。

## B. 错误处理与失败

- **#A05 裸 except 吞错误**（[事故]）：`except: pass` 把失败变静默，症状消失但结果全错。→ 禁止吞错；失败显式记录/上报；负面证据也是数据。
- **#A06 产物不注册**（[事故]）：研究循环给自己打分，验证证据全丢，结果不可核对。→ 系统注册自己的产物（artifact registry）。
- **#A07 单点无守卫**（[事故]）：网关进程挂掉，所有 cron/自动化/通信停摆，无告警无自重启。→ 关键进程 watchdog + 告警 + 自重启。
- **#A08 配置变更级联崩溃**（[事故]）：改模型/endpoint 后全系统行为突变。→ 配置快照不可变、变更后跑健康检查、灰度放量。
- **#A09 无限重试**（[社区]）：失败后死循环重试，越撞越卡。→ 指数退避 + 最大重试次数 + 熔断。
- **#A10 无降级路径**（[逆向]）：依赖挂了整个 agent 跟着崩。→ 分层降级：真实→mock/缓存→简化响应。

## C. LLM 与幻觉

- **#A11 模型"伪装"不确认**（[事故]）：无法验证信息却自信回答（"don't fake it"）。→ 提示词强制"不知道就说不知道"；无法核验就明说。
- **#A12 只靠向量检索就完事**（[文献]）：RAG 把检索块扔给模型就指望不幻觉。→ 引用溯源 + 3 层幻觉检测 + 置信度阈值（见 03#1）。
- **#A13 429/限流混淆**（[事故]）：把限流报错当别的错，配置错位排查半天。→ 错误码显式区分；日志记录原始错误。
- **#A14 配置字段不匹配**（[事故]）：模型名/endpoint 字段拼错，调用静默失败。→ 启动时校验配置契约；schema 恒定测试。
- **#A15 上下文塞满工具返回**（[文献]）：工具返回大文档撑爆上下文。→ 返回截断/摘要；只回填关键信息。

## D. 权限与安全

- **#A16 新工具默认可执行**（[support]）：没标敏感的工具被模型直接执行高风险操作。→ fail-closed：新工具默认敏感，显式声明才绕过。
- **#A17 只靠提示词防越权**（[逆向]）："请别乱来"可被注入绕过。→ 硬性权限（fail-closed + 单调收窄），不靠嘴。
- **#A18 子代理权限放大**（[逆向]）：子代理拿到父代理更多权限。→ 单调权限收窄：子 ⊆ 父。
- **#A19 API key 泄露**（[事故]）：密钥进代码/日志/提交历史。→ 环境变量/密钥管理器；泄露立即轮换；日志脱敏。
- **#A20 角色提权**（[support]）：注册/操作时篡改角色字段提权。→ 服务端校验角色，不接受客户端声称；越权 403。

## E. 记忆

- **#A21 记忆无边界存储**（[社区]）：什么都存，检索噪声大、上下文污染。→ 5 类分型 + 引导规则（何时存/何时清）。
- **#A22 记忆冲突不治理**（[社区]）：新事实和旧矛盾，agent 混乱。→ correct 纠正 + consolidate 检测矛盾 + governance 隔离低置信。
- **#A23 会话结束不清理**（[社区]）：工作记忆残留，下次会话误用。→ 结束 purge working + 存 episodic 摘要。
- **#A24 记忆实验不可回滚**（[社区]）：改记忆库改坏了没法恢复。→ 快照/分支/回滚（Git for memory）。

## F. HITL 与状态

- **#A25 HITL 确认被绕过**（[support]）：确认弹窗是摆设，直接执行。→ 确认前不落库、后端强制校验、防重复。
- **#A26 HITL 滥用**（[文献]）：什么都弹确认，体验崩。→ 只对高风险/不可逆操作用 HITL。
- **#A27 状态机非法转移**（[support]）：工单/任务状态乱跳（如直接 closed→resolved）。→ 显式状态机拒绝非法转移 + 转换日志审计。

## G. 交付与运维

- **#A28 无评估就上线**（[文献]）："感觉能用"代替度量，变坏没人知。→ 离线评估集 + 在线监控（指标/trace/告警）。
- **#A29 评估集和真实数据脱节**（[文献]）：自测全过、线上翻车。→ 评估集覆盖 BDD 场景 + 对抗用例 + 真实数据抽样。
- **#A30 SSE 被代理缓冲**（[support]）：生产反代缓冲 SSE，实时变延迟/卡顿。→ nginx 反代关 SSE 缓冲（proxy_buffering off）。
- **#A31 WebSocket 无反代**（[社区]）：Next.js 不原生代理 WS 升级，语音/实时功能失效。→ 反代转发 /ws/*；getUserMedia 需 HTTPS 安全上下文。
- **#A32 依赖进程配置缺失**（[社区]）：Redis 没设 vm.overcommit_memory=1，重启丢数据。→ 按部署清单逐项配置主机级参数。
- **#A33 TTS/多语言模型限制**（[社区]）：本地 TTS 只有英语，多语言学习场景出不了音频。→ 选型前确认模型语言支持，必要时切云端。
- **#A34 中文路径/编码坑**（[事故]）：工具在中文路径/编码下解析失败（YAML 路径分隔符、编码陷阱）。→ 跨平台路径/编码契约测试。
- **#A35 变更前不备份**（[社区]）：重置数据库/删表前没备份，误操作无法恢复。→ 破坏性操作前备份 + 确认。

## H. 双轨与测试

- **#A36 只测 mock 不测 real**（[support]）：mock 全过，真实 LLM 协议对不上。→ 双轨都测：真实 LLM 工具协议契约测试（schema 恒定）。
- **#A37 工具 schema 描述模糊**（[文献]）：模型不知道工具干嘛，乱调或不调。→ schema 描述写清楚输入/输出/用途，附示例。
- **#A38 测试吞异常**（[support]）：测试里宽泛 except 掩盖真实错误。→ 断言具体异常类型，不吞。
