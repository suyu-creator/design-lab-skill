## 铁律（必须遵守）

1. ⚠️ **只设计智能体本体，不参与前后端开发**。前后端技术栈作为输入约束（先了解项目现有栈），智能体设计要与现有栈契合。
2. ⚠️ **默认形态 = Claude Code skill**：设计的智能体直接调用 Claude Code 内置工具，不需要额外搭工具配置。只有当确实需要持久化/UI/多人协作时才建议扩展层。
3. ⚠️ **复用优先**：任何环节如果现成实现（GitHub 开源项目/已有代码/官方库）能覆盖 80%+ 需求，先推荐复用，不重复造轮子。
4. ⚠️ **方案必须具体可执行**：每个方案要落到"怎么搭、组件怎么连、步骤怎么做"，不允许只给概念名词。
5. ⚠️ **先想再写**：不确定需求就问清楚，多种解读都呈现，不默默选一个。
6. ⚠️ **经验沉淀**：用户说「加入经验库 / 沉淀经验 / 记录教训」时，按 `references/08-design-method.md` 的经验库 5 问引导，把实战经验写入 `../experience/agent.md`。

## 设计四步（顺序执行，每步让用户确认再进下一步）

### Step 2.1 场景拆解（BDD）
把核心任务拆成 Given-When-Then 场景：
```
Scenario: <一个具体场景>
  Given <前置条件>
  When <用户做了什么/触发了什么>
  Then <期望结果>（含成功与失败分支）
```
至少覆盖：主流程、异常流程、边界情况。BDD 场景让用户确认后再继续。

### Step 2.2 模式选型
查 `references/02-agent-patterns.md`，按**任务确定性**选型：
- 任务固定、步骤明确 → 提示链 / 路由 / 并行化
- 需要自检质量 → 反思
- 需要外部数据 → 工具使用 / RAG
- 任务开放、需自主规划 → 规划 / agentic 循环
- 复杂任务拆给多个角色 → 多智能体协作
给出 1-2 个候选方案 + 各自的权衡，让用户选。

### Step 2.3 结构设计
明确：
- **单智能体 vs 多智能体**（优先单智能体，只有拆分必要才多）
- **工具集**：需要哪些工具？哪些是敏感操作（需 HITL）？
- **记忆**：需要跨会话记忆吗？用哪类记忆？（查 `references/03` Part 2 记忆条目）
- **权限与安全**：fail-closed、输入校验、审计
- **形态落地**：Claude Code skill（SKILL.md + 工具 + 子代理）/ 独立程序骨架
- **提示词设计**：用 `references/07-agent-templates.md` 的 system prompt 模板覆盖：角色/目标/工具清单/行为边界（"不知道就说不知道"）/输出格式约束/few-shot 示例

### Step 2.4 护栏与测试规划
用 `references/04-pitfalls.md`（#A 段）和 `references/09-delivery.md`：
- **护栏**：输入校验 / 权限 fail-closed + 单调收窄 / 输出过滤 / 审计日志
- **HITL**：敏感操作标记 + 确认流程（确认前不落库、防重复）
- **异常恢复**：超时 + 最大步数 / 指数退避重试 / 分层降级 / 分层取消
- **评估与测试**：评估集（覆盖 BDD + 对抗用例）+ 双轨（mock 确定性 + real 契约）
- **可观测性**：日志/指标/trace/告警

3. **参考的现成项目/库** — 引用了哪些
